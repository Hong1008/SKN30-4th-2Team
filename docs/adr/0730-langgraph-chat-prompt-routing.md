# LangGraph 기반 질문 분류와 근거 제한 채팅

- 상태: Accepted
- 날짜: 2026-07-30

## 맥락

단일 프롬프트가 계약서 전체 검토 결과, 특정 조항, 검토 상태, 카테고리와
법령 근거를 동시에 처리하면서 9B 양자화 모델이 질문의 대상을 안정적으로
선택하지 못했다. 전체 계약에 관한 질문에도 특정 조항을 임의로 선택하거나,
주의 신호의 의미를 묻는 질문에 조항 원문만 반복하는 문제가 있었다.

정규식으로 질문 의도를 분기하면 표현 변형과 이전 대화의 생략된 대상을
다루기 어렵다. 반대로 모든 MCP 자료와 지침을 하나의 프롬프트에 넣으면 제한된
문맥에서 관련 근거가 희석되고 작은 모델이 수행해야 할 판단이 많아진다.

## 결정

### 질문 처리 그래프

LangGraph `StateGraph`로 다음 단계를 고정한다.

1. 분류 모델이 현재 질문과 최근 대화만 보고 질문 유형 라벨 하나를 선택한다.
2. 선택한 유형에 필요한 검토 결과와 MCP 자료만 조회해 문맥을 구성한다.
3. 유형별 지침, 제한된 문맥과 사용자 질문을 답변 모델에 전달한다.
4. 분류 실패, 범위 밖 질문 또는 필수 근거 부재는 답변 모델 호출 전에
   종료한다.

분류 모델과 답변 모델은 별도 의존성, provider 설정과 호출 예산을 사용한다.
`ROUTER_LLM_PROVIDER`와 `ROUTER_LLM_MODEL`을 함께 지정하면 분류기만
OpenAI 또는 Gemini 같은 저지연 provider를 사용할 수 있다. 두 설정을 생략하면
기존 `LLM_PROVIDER`와 `LLM_MODEL`을 사용해 배포 호환성을 유지한다.
운영 답변 모델에 대한 `LLM_PROVIDER=vllm` 제한은 그대로 유지한다.

- 분류 모델: temperature 0, 최대 생성 8토큰, 기본 제한 시간 3초
- 답변 모델: temperature 0, 최대 생성 512토큰
- 검색된 문서 블록: 최대 512자
- 대화 기록: 최근 2개 발화만 사용

외부 분류기에는 현재 질문 최대 80자와 최근 대화의 짧은 발췌, 라벨 정의만
전달한다. 계약서 원문, 검토 결과와 MCP 법령 자료는 분류 호출에 포함하지
않는다. 분류 지연은 질문 본문 없이 유형, 성공 여부와 처리 시간만 기록한다.

### 질문 유형

분류 모델은 아래 라벨 중 하나만 반환한다.

| 라벨 | 범위 |
| --- | --- |
| 조항 질문 | 특정 사용자 조항의 내용과 대응 표준조항 후보 |
| 검토 결과 질문 | 계약서 전체 검토 결과와 누락 후보 요약 |
| 검토 분류 질문 | 검토 상태 라벨과 주의 문구 유사 신호의 의미 |
| 조항 카테고리 질문 | MCP 카테고리 이름과 설명 |
| 조항 법령 근거 질문 | MCP 법령명, 조문과 원문 참고자료 |
| 선정 불가 | 현재 계약 검토 자료로 답할 수 없는 질문 |

분류 프롬프트에는 각 라벨의 짧은 정의와 퓨샷 예시를 포함한다. 정규식이나
키워드 분기 로직은 사용하지 않는다. provider의 JSON Schema 구조화 출력으로
`QuestionCategory` enum 하나만 받으며, 스키마 파싱에 실패하면 임의의
카테고리로 보정하지 않고 출력 오류로 처리한다.

### 유형별 근거 제한

- 조항 질문은 선택 조항이 있으면 해당 사용자 조항과 대응 표준조항 후보만
  사용한다.
- 검토 결과 질문은 `clause_results`와 `missing_standard_clauses`를 서로 다른
  의미의 목록으로 유지해 전달한다.
- 검토 분류 질문은 사용자용 검토 상태 라벨과
  `list_toxic_pattern_details`의 주의 신호 이름만 사용한다.
- 조항 카테고리 질문은 `list_categories`가 제공한 이름과 설명만 사용한다.
- 조항 법령 근거 질문만 `get_category_grounding`을 호출한다. 조회 상태가
  `OK`이고 원문 항목이 있을 때만 답변 모델을 호출한다.
- 선정 불가 질문은 MCP와 답변 모델을 호출하지 않고
  `제공된 문서에서 관련 정보를 찾을 수 없습니다.`를 반환한다.

내부 상태와 enum 코드는 답변 문맥에서 사용자용 라벨로 변환한다. 주의 신호는
법률 판단이 아니라 알려진 주의 문구와의 유사 신호로만 설명한다. 법령 원문도
참고자료로만 제공하며 위법·적법, 유효·무효 또는 계약상 유불리를 단정하지
않는다.

## 결과

작은 모델이 한 번의 호출에서 질문 분류, 근거 선택과 답변을 동시에 수행하지
않게 된다. 질문 유형마다 근거 범위가 좁아져 특정 조항의 임의 선택과 관계없는
법령·카테고리 사용 가능성이 줄어든다. 범위 밖 질문과 법령 근거 부재는 생성
전에 차단되므로 문서에 없는 답변을 만들 기회도 줄어든다.

대신 일반 질문마다 분류 모델 호출이 한 번 추가되어 지연 시간과 모델 사용량이
늘어난다. 외부 저지연 모델을 선택하면 네트워크와 provider 장애에 의존하고,
사용자가 질문에 직접 붙여 넣은 문구는 외부로 전달될 수 있다. 분류 오류가 답변
경로를 결정하므로 provider 전환 전 라벨별 회귀 테스트와 실제 모델 평가가
필요하다. 새로운 질문 유형이나 MCP 자료 범위를 추가할 때는 분류 라벨,
JSON Schema, 유형별 프롬프트, 문맥 구성과 테스트를 함께 변경한다.

코드 줄 수 자체는 더 이상 설계 제약으로 삼지 않는다. 중복을 피하되 분류
경계, 근거 선택과 실패 처리가 읽히는 구조를 우선한다.
