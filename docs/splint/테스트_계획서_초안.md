## 1. 목적 및 범위

- 목적: 발표 시연에서 업로드부터 결과·조항 상세·챗봇·협의 문구까지 끊기지 않는 핵심 흐름과, 데모를 중단시킬 수 있는 오류 복구를 확인한다.
- 포함: 정상 시연, 빈 문서·업로드 오류, 파일 제거, 결과 새로고침 복구, 결과 화면 상태 동기화·표시, 챗봇 정상·거절 응답, 협의 문구 안전성, RunPod·LLM 오류 안내.
- 제외: 대화 이력 복구, 일반 사용자 배포 검증, 다중 브라우저/CORS 매트릭스, 장기 TTL, 대기열 부하, vLLM OOM, 프롬프트 인젝션 심화, 법률 판단·MCP 매칭 품질, MVP 이후 기능.

## 3. 진입·종료 기준

| 구분 | 기준 |
| --- | --- |
| 진입 | 시연 URL 접속, RunPod·MCP 연결, 정상 PDF와 오류용 파일 준비 완료 |
| 종료 | 적용 가능한 13개 케이스가 모두 PASS이고, 발표용 브라우저에서 정상 흐름을 1회 완료함 |

### 발표 필수 통과 기준

- 적용 가능한 케이스 중 하나라도 실패하면 우회 시연 경로를 준비하거나 해당 기능을 시연 범위에서 제외한다. 안전한 오류 주입 수단이 없는 `DEMO-05`는 사유와 함께 미실행으로 기록할 수 있다.
- 자동화 케이스는 실행 결과를, 수동 케이스는 화면 캡처 또는 짧은 영상만 남긴다.
- API 상태 코드보다 화면의 다음 행동 안내와 화면 전환이 기대 결과에 맞는지 우선 확인한다.

## 6. 자동화 실행과 증적

```bash
cd api && uv run pytest tests/api_v1/test_session_review_routes.py
cd web && npm test -- --run src/api/api.test.ts src/screens/UploadAndTypeScreen.test.tsx
```

| 항목 | 확인하는 굵직한 결함 |
| --- | --- |
| API 세션 테스트 | 파일·DB 레코드·Cookie 삭제, 저장소 삭제 실패 시 세션 보존, 빈 문서의 검토 시작 차단 |
| 프론트 업로드 화면 테스트 | 빈 문서 정리 성공·실패, 파일 삭제 실패, 삭제 중 유형 선택·검토 시작 차단 |
| 프론트 API 테스트 | 업로드 60초·세션 삭제 15초 시간 초과 시 abort와 재시도 안내 |
| 최신 UI 수동 확인 | 검토 중 스테퍼가 화면 이동을 일으키지 않는지, 미완료 결과가 진행 화면으로 복귀하는지, `NO_MATCH`·누락 조항이 사용자용 정보로 표시되는지 |
| LLM 수동 확인 | 챗봇 답변·거절·출처, 협의 문구의 근거·`[확인 필요]`·생성 제한, LLM 오류 시 사용자 안내 |

기록할 증적은 케이스 ID, PASS/FAIL, 실행 시각, 화면 캡처 또는 테스트 출력뿐이다. LLM 화면 캡처에는 계약서 원문·조항 전문·대화 전문·토큰·내부 ID가 보이지 않도록 한다.

## 7. 결과서 작성 예정 항목

본 문서는 발표 시연 전 테스트 계획서다. 테스트 실행 후 결과서에는 아래 항목을 추가한다.

- **시연 입력값:** 사용한 시연 PDF의 식별명, 정상·거절 질문 문구, 협의 문구 대상 조항과 기대 출처를 기록한다. 계약서 원문·조항 전문·개인정보는 기록하지 않는다.
- **결과 요약:** `DEMO-00`~`DEMO-12`별 PASS/FAIL/미실행, 실행 시각, 증적 위치와 총계(PASS/FAIL/미실행)를 기록한다.
- **결론:** 발표 시연 가능 여부, 실패·미실행 항목의 사유와 우회 시연 경로, 발표 이후 보완할 검증 범위를 정리한다.

## 8. 발표 직전 체크 순서

1. `DEMO-00` 배포·LLM 사전 점검을 수행한다.
2. `DEMO-06` 자동화 테스트를 실행한다.
3. 시연 PDF로 `DEMO-01`을 수행한다.
4. `DEMO-09`, `DEMO-10`, `DEMO-11`로 LLM 정상·거절·안전성을 확인한다.
5. `DEMO-02`, `DEMO-03`, `DEMO-04`, `DEMO-07`, `DEMO-08`을 빠르게 확인한다.
6. RunPod 상태를 확인하고 `DEMO-05`, `DEMO-12`의 오류 안내 문구를 공유한다.
7. 정상 PDF와 결과 화면을 열린 상태로 발표를 시작한다.
