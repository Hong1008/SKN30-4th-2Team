## 1. 목적 및 범위

- 목적: 계약서 업로드부터 계약 유형 선택, 검토 진행, 결과·법령 근거·협의 문구·챗봇까지의 실제 웹앱 통합 흐름을 검증한다.
- 포함: 기능, API·MCP 통합, 상태 전이, SSE·폴링 복구, 세션·보안·삭제, 제한 큐, 발표 시연 E2E.
- 제외: 법률 판단의 정확성 보증, MCP 검색·매칭 품질 재측정, 실제 사용자 대상 장기 부하 시험, MVP 이후 기능.

> Ollama 통합 검증 결과와 RunPod vLLM 발표 시연 결과는 모델·응답시간·구조화 출력이 다를 수 있으므로 같은 결과로 간주하지 않는다.

## 5. 공통 기록 기준

각 실행 케이스에는 아래 항목을 기록한다.

| 기록 항목 | 값 |
| --- | --- |
| 식별 | 케이스 ID, 실행일, 실행자, 웹앱 URL |
| 요청·세션 | 파일명, 세션 ID, `review_id`, 선택 계약 유형 |
| 응답 | HTTP status, 실제 API 상태, 오류·특이사항 |
| 판정·증적 | PASS/FAIL/BLOCKED, 캡처·영상·로그 링크 |
| 챗봇·법령·문구 추가 기록 | `grounding_status`, `sources.LAW`, `outcome`, `answer/text`, `required_confirmations`, `tool_status`, `retryable`, `next_action` |

| PR-N/E | 진행·SSE | `QUEUED`→`REVIEWING`→`COMPLETED`, 강제 종료·재연결 | SSE 우선, 오류 시 단일 폴링, sequence 역행 방지 | 높음 | 미실행 |

| CH-N/E | 챗봇 | 근거 범위 질문, 법률 결론 요구, 프롬프트 인젝션 | 근거·출처만 표시, 추측·명령 실행 차단 | 높음 | 미실행 |
| SE-N/E | 세션·보안 | 소유권, TTL, 연장, 새 검토·취소, 로그 | 세션 격리, 대화·임시파일 정리, 로그 본문 미기록 | 높음 | 미실행 |

| E2E-01 | 발표 시연 | 업로드→유형→검토→결과→법령→문구→챗봇 | 전체 흐름과 새 검토·만료 초기화 확인 | 높음 | 미실행 |
