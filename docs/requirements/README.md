# 요구사항·기획 문서

WorkShield의 사용자 요구사항, 상태 전이, 운영 정책, 화면 동작과 요구사항별
세부 참조를 관리합니다. API의 최종 계약은 `docs/api/openapi.json`을 기준으로
하며, 이 폴더의 문서는 사용자·화면·운영 관점의 기획 기준입니다.

## 문서 구성과 우선순위

| 구분 | 파일 | 역할 |
|---|---|---|
| 요구사항 원본 | `요구사항.json` | FR ID, 범위, 구현·검증 책임의 기준 데이터 |
| 요구사항 요약 | `요구사항.md` | 사용자 관점의 확정 요구사항 요약 |
| 상태 머신 | `서비스_전체_흐름도.json` | 화면·검토·세션 상태와 전이의 기준 |
| 운영 정책 | `운영_정책.json` | 데이터 보관, 보안, 자원 제한, 오류 처리 정책 |
| 사용자 흐름 | `사용자 흐름·상태 정의서 초안.md` | 상태 머신을 사용자 경험으로 해석한 문서 |
| 화면 기능 | `화면별_기능_정의서.md` | 화면별 기능, 예외 흐름, QA 기준 |
| 협업 설계 | `개발협업용_화면설계서_초안.md` | 프론트·백엔드 협업용 UI·DTO·전달 기준 |
| 세부 참조 | `ref/*.json` | 기능 영역별 요구사항 원본의 분할 참조 |
| 시각 요약 | `*_요약.png`, `*_요약.svg`, 화면설계서 PDF | 발표·공유용 요약 산출물 |

같은 정책이 여러 문서에 나타날 때는 `요구사항.json`,
`서비스_전체_흐름도.json`, `운영_정책.json`을 먼저 맞추고, Markdown과
`ref/*.json`을 같은 내용으로 동기화합니다.

## 현재 세션 정리 기준

- 사용자의 파일 제거·새 검토 시작·명시적 종료에서는 서버 삭제를 요청한다.
- 페이지 이탈·브라우저 종료에서는 삭제 요청을 보장하지 않으며, 서버가 최대
  30분 TTL 후 임시 세션·원본 파일을 정리한다.
- 빈 문서는 `REUPLOAD_REQUIRED` 상태로 처리하며, 생성된 세션 정리에 실패하면
  세션을 보존해 사용자가 파일 제거를 재시도할 수 있게 한다.
